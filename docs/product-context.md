# Контекст продукта

Дополняет `README.md`: сценарии использования, термины и границы текущей и планируемой функциональности.

## Основные сценарии

- Отслеживание новых/популярных репозиториев по языку и/или теме (например, `--language python --topic machine-learning`).
- Быстрый срез «что сейчас в тренде» по минимальному числу звёзд (`--min-stars`).
- Экспорт списка для дальнейшего ручного просмотра в Excel/Sheets (`.csv`) или для передачи в другой скрипт/инструмент (`.json`).

## Доменные термины

| Термин | Значение |
|---|---|
| `language` | Язык программирования репозитория по данным GitHub (поле `language` в ответе API) |
| `topic` | Тег темы, который владелец репозитория указал в настройках GitHub |
| `stars` | Количество звёзд (`stargazers_count`) — единственная метрика популярности, которую использует инструмент |
| fallback-запрос | Запрос по умолчанию (`stars:>1000`), если не указан ни один фильтр — иначе GitHub Search API отклонил бы пустой запрос |

## Критерии полезного результата

Результат считается полезным, если:
- количество найденных репозиториев соответствует ожиданиям по заданным фильтрам (не 0, если фильтры разумные);
- в CSV/JSON присутствуют все шесть полей (`name`, `stars`, `language`, `topics`, `url`, `description`) для каждого репозитория;
- значения `language`/`description` не ломают формат при отсутствии данных (GitHub может вернуть `null` — инструмент подставляет пустую строку, см. `github_search.py:fetch_repos`).

## Пример вывода

Команда:
```bash
python github_search.py --topic ai-agents --min-stars 500 --output out.json
```

Фрагмент `out.json`:
```json
[
  {
    "name": "example-org/agent-framework",
    "stars": 5230,
    "language": "Python",
    "topics": "ai-agents, llm, automation",
    "url": "https://github.com/example-org/agent-framework",
    "description": "Framework for building autonomous AI agents"
  }
]
```

## Ограничения GitHub Search API

- Без авторизации: 10 запросов/минуту, максимум 1000 результатов на один поисковый запрос (ограничение самого Search API, не этого инструмента).
- `per_page` (наш `--limit`) — максимум 100 за один вызов.
- Поиск учитывает только публичные репозитории.

Ниже — краткие спеки для нереализованных пунктов из `README.md`. Это планирование, не обязательство сделать в ближайшее время (см. `AGENTS.md` → «Out of scope for now»).

### Сохранение истории запросов

- **Ожидаемое поведение:** каждый запуск с непустым результатом дописывает строку в локальный файл истории (запрос, дата, количество найденных репозиториев).
- **Формат данных:** построчный JSON (JSONL) или CSV с колонками `timestamp`, `query`, `count`.
- **Крайние случаи:** пустой результат — не пишем в историю; параллельные запуски — не гарантируем atomicity записи.
- **Способ проверки:** тест на то, что после `main()` файл истории содержит новую строку с ожидаемыми полями.

### Авторизация через токен GitHub

- **Ожидаемое поведение:** если задана переменная окружения `GITHUB_TOKEN` (см. `.env.example`), запросы идут с заголовком `Authorization`; если нет — текущее поведение без изменений.
- **Формат данных:** без изменений в структуре `Repo`/CSV/JSON.
- **Крайние случаи:** невалидный токен — GitHub вернёт 401, инструмент должен явно сообщить об этом, а не падать сырым traceback'ом.
- **Способ проверки:** тест с моком, что заголовок `Authorization` присутствует при заданном токене и отсутствует без него.

### Сравнение трендов по нескольким языкам

- **Ожидаемое поведение:** несколько независимых запросов (по языку), сведённые в один сравнительный отчёт (например, топ-N репозиториев на язык бок о бок).
- **Формат данных:** отдельный агрегированный CSV/JSON с колонкой `language` для группировки.
- **Крайние случаи:** язык без результатов — отражается в отчёте нулём, а не пропускается молча.
- **Способ проверки:** тест на агрегацию нескольких замоканных ответов `fetch_repos()` в один отчёт.
